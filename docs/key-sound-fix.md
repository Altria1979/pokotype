# 短促电子按键音修复

五十音与文章练习统一使用约 420Hz、90ms 的短促电子音，替换原有偏轻的机械合成音。试听使用同一播放路径。现有音效开关、25% 默认音量和已保存偏好保留，零音量仍然表示静音。

## 实现与文件

- `src/lib/audio.ts`：删除机械声的噪声缓冲及滤波节点，每个声音仅需振荡器和增益节点；加入淡入淡出、最多四个同时发声的限制和输出余量。首次恢复音频上下文时，仅播放100ms内最新的一次输入，不积攒补播。
- `src/components/useBrowserAudio.ts`：按键故障与语音朗读提示独立，不互相覆盖。
- `src/components/Practice.tsx`、`SoundSettings.tsx`：复用现有控件，增加零音量说明、声音设置入口和「重试按键音」。取消冗余的试听恢复代次管理，由音频控制器统一负责。
- `src/lib/audio.test.ts`：恢复、取消、重试、资源释放、上下文重建与StrictMode回归。
- `tests/audio-native.spec.ts`：原生AudioContext、真实节点与实际音频时钟，通过AnalyserNode采样输出波形，验证有声、静音、频率与连续输入的峰值。
- `tests/audio-practice.spec.ts`、`audio-settings.spec.ts`：保留朗读与计分回归，补充重试、提示独立和零音量说明。
- `tests/home-routing.spec.ts`：首键前等待练习区取得焦点，并核对错键反馈，避免导航提交前输入造成测试误判。

关闭音效、暂停、退出与销毁均取消待恢复声音；旧恢复请求失效后，新的用户手势可独立重试。正确与错误字母使用同一声音，快捷键、输入法组合输入、长按重复、暂停和整句听读中的字母不触发按键音。

未增加依赖、音色选择器或持久化字段，未改变练习路由、输入匹配规则和朗读配置。

## 验证

- Lint、TypeScript、203项单元测试和静态构建通过。
- 最终完整Chrome浏览器回归85/85通过，无跳过、失败或重试通过项，覆盖五十音、文章、声音设置及原有生成与导航流程。报告：`.omx/artifacts/key-sound/full-final.json`；汇总：`.omx/artifacts/key-sound/validation-summary.json`。
- 原生Chrome采样连续三轮通过：使用8192点采样窗，覆盖完整短音以避免动画帧抖动漏采。默认25%单键峰值0.08313–0.08330、RMS约0.01410、主频421.875Hz；100%试听与文章单键峰值均约0.16547，32次快速连按峰值最高0.41685，未达到数字削波范围。关闭、零音量、暂停、退出和尾音结束后的15次静音采样峰值均为0。这些是本机测试读数，不是所有设备的固定输出；详见 `.omx/artifacts/key-sound/pcm-summary.json`。
- 内置浏览器已核对现有偏好为音效开启、音量25%，实际点击新版试听，并在文章练习输入字母；未出现播放提示或控制台错误，验证后结束未完成练习。
- 1440px练习重试/零音量提示、390px设置零音量提示截图通过，无横向溢出。截图位于 `.omx/artifacts/key-sound/`，视觉核对见 `.omx/state/key-sound/ralph-progress.json`。

输出信号测试不等同于扬声器与耳机的人工听感评价；系统音量、静音状态与输出设备仍会影响实际听感。本次未做其他浏览器的完整回归。
